Agent approvals

Your coding agent asks before it acts. Claude Code pauses, your phone buzzes, you tap Approve or Deny on the lock screen, and it carries on — even when you're nowhere near the terminal.

What it does

Start an agent on a server and walk away, and you normally lose it: the moment it needs permission it sits at a prompt nobody is watching. Agent approvals close that loop.

Claude Code (on your server) │ about to run rm -rf build/ ▼ inbox.plingpush.com — holds the request open │ ▼ your iPhone — push with Approve / Deny │ you tap Approve ▼ Claude Code continues ✓

Nothing is installed on the host. Claude Code hooks are plain configuration, so this is a few lines of JSON in ~/.claude/settings.json and an environment variable.

Set it up

The Pling app does all of this for you over the SSH connection it already has.

Add the host to Pling

Any SSH host works — it doesn't need the Pling agent installed.

Open the host menu

On the Hosts tab, tap … next to the host (or long-press it) and choose Agent approvals.

Tap Enable approvals

Pling creates a token for that host, merges the hook into ~/.claude/settings.json without touching your own hooks, and stores the token in a private file on the host.

Open a new shell on the host

So the token is exported. That's it — the next tool call asks your phone.

Which tools ask? By default Bash, Write, Edit and NotebookEdit — the ones that change a machine. Reads and searches run without interrupting you.

Manual setup

Prefer to configure it yourself, or running an agent somewhere Pling can't reach? Merge this into ~/.claude/settings.json on the host.

{
  "hooks": {
    "PreToolUse": [{
      "matcher": "Bash|Write|Edit|NotebookEdit",
      "hooks": [{
        "type": "http",
        "url": "https://inbox.plingpush.com/api/hooks/claude-code?timeout=300",
        "timeout": 330,
        "headers": { "Authorization": "Bearer $PLING_SOURCE_TOKEN" },
        "allowedEnvVars": ["PLING_SOURCE_TOKEN"]
      }]
    }]
  }
}
Keep the client timeout above the server one. The timeout field must be larger than the ?timeout= value. Claude Code treats its own timeout as non-blocking — it would run the command anyway — so the server's deny needs to land first.

Host token

The hook reads your token from the environment, so it never sits in a file you might commit. Create one in Pling under Agent approvals, then on the host:

$ echo 'export PLING_SOURCE_TOKEN=your_token_here' > ~/.pling-agent-env
$ chmod 600 ~/.pling-agent-env
$ echo '[ -f "$HOME/.pling-agent-env" ] && . "$HOME/.pling-agent-env"' >> ~/.zshrc

One token per host. Revoking it in Pling immediately stops that host from raising approvals.

Get a push when a session finishes

Add a Stop hook. The endpoint returns immediately, so it barely pauses the session:

{
  "hooks": {
    "Stop": [{
      "hooks": [{
        "type": "http",
        "url": "https://inbox.plingpush.com/api/hooks/notify",
        "timeout": 10,
        "headers": { "Authorization": "Bearer $PLING_SOURCE_TOKEN" },
        "allowedEnvVars": ["PLING_SOURCE_TOKEN"]
      }]
    }]
  }
}

Endpoints

Both authenticate with a host token as Authorization: Bearer <token>.

EndpointBehaviour
POST /api/hooks/claude-codeBlocks until you answer, then returns Claude Code's permissionDecision.
POST /api/hooks/notifyRecords an update and pushes. Returns immediately.
GET /api/inboxYour pending and recent agent activity.

Failure behaviour

An approval gate is only worth having if it's safe when things break. This one fails closed:

  • Nobody answers in time → denied.
  • Token revoked or invalid → denied.
  • Server error on our side → denied.
  • You dismiss the request in the app → denied.
One case we can't cover. If the host loses its network connection entirely, Claude Code never reaches us — and it treats an unreachable hook as non-blocking, so the command runs. That's Claude Code's behaviour, not a setting we control. Approvals are a safety net for unattended work, not a security boundary.

Other agents

Codex, Cursor and Aider have no hook system, so they can't request approvals this way yet. They can still send you updates through the push API — a line in a wrapper script is enough to get a notification when a run finishes or fails.

Agent approvals are part of Pling Pro, alongside push notifications, server monitoring and session sharing.
